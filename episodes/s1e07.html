L'autorisation

La demande part avec les données de la transaction, et l'émetteur ne sait pas ce que vous achetez. Le résultat de la réponse tient sur deux caractères.

5 min · lecture 4 concepts 4 quiz
Concept 1 / 4 · La demande d'autorisation

L'émetteur ne voit pas ce que vous achetez

Quand vous payez, le terminal envoie une demande d'autorisation à l'émetteur de la carte. Elle porte le montant et la devise, l'identité du commerçant et du terminal, le code d'activité, le mode de lecture et les données EMV lues sur la puce, dont un cryptogramme. L'émetteur décide à partir de ce contexte, celui de la carte, du terminal et du commerçant. Le ticket et les articles n'y figurent pas.

À droite, ce que reçoit l'émetteur. À gauche, ce qui reste chez le commerçant.

Le cryptogramme est calculé par la puce au moment du paiement. Il permet à l'émetteur d'authentifier la carte utilisée. Un cryptogramme intercepté ne peut pas être réutilisé : il est lié à la transaction en cours.

Le nom que le client voit dans son appli bancaire vient de l'acquéreur. Un nom incorrect, ou la raison sociale à la place de l'enseigne, se corrige chez lui.

À retenir : le code d'activité (MCC, Merchant Category Code) compte 4 chiffres, attribués au commerçant par son acquéreur à l'ouverture. 5411 pour les supermarchés, 5812 pour les restaurants, 5541 pour les stations-service, 7995 pour les jeux d'argent. L'émetteur s'en sert pour évaluer le risque, davantage en ligne qu'en magasin. Il pèse aussi sur les frais : les activités à risque, comme les jeux d'argent, sont facturées plus cher, et certains acquéreurs refusent des secteurs entiers.

Concept 2 / 4 · Le trajet de la demande

Où passent les deux secondes

Du bip à la réponse, une autorisation en ligne dure environ deux secondes. La demande passe par le terminal, l'acquéreur, le réseau de cartes et l'émetteur, puis la réponse refait le chemin inverse.

Les opérations sur le terminal sont les plus longues : il prépare le message et ouvre une connexion sécurisée. Elles s'exécutent en local. Le trajet vers l'acquéreur s'appuie sur le réseau internet. L'aller-retour jusqu'à l'émetteur, réseau de cartes compris, tient en moyenne en moins d'une demi-seconde. Si la réponse n'arrive pas, le terminal attend, puis annule l'opération (reversal).

À retenir : l'autorisation n'est pas le paiement : elle réserve les fonds, elle ne transfère rien. Ce qui se passe après, on l'abordera à l'épisode suivant.

Concept 3 / 4 · Le code de réponse

Un code, pas une phrase

La réponse de l'émetteur tient sur deux caractères : 00 pour accepté, et une centaine d'autres valeurs pour les refus et les cas particuliers. Les plus emblématiques :

CodeMessage
05Do not honor
51Insufficient funds, fonds insuffisants
54Expired card, carte expirée
43Stolen card, carte déclarée volée

Les tables ne sont pas identiques d'un réseau ou d'un acquéreur à l'autre, et certains refus viennent du terminal lui-même (carte expirée, carte non supportée).

À retenir : le code 05 indique un refus, mais ne l'explique pas : c'est un code d'erreur générique.

Concept 4 / 4 · L'authentification forte

Le seul refus qui n'en est pas un

Parfois, l'émetteur ne refuse pas : il demande de s'identifier à nouveau, au titre de l'authentification forte (DSP2). Le code est 1A chez Visa et 65 chez Mastercard. En ligne, le site envoie le client confirmer dans l'application de sa banque, puis relance la demande. En magasin, le terminal demande le code PIN.

Fraude sur les paiements par carte sur internet, en € pour 100 000 € payés. Source : Observatoire de la sécurité des moyens de paiement (OSMP, Banque de France), rapport annuel 2025.

À retenir : l'authentification forte combine deux éléments parmi trois : ce que l'on sait (le code PIN), ce que l'on possède (le téléphone, la carte), ce que l'on est (l'empreinte, le visage).
Mon avis
Avoir l'argent sur son compte ne suffit pas : chaque carte a ses propres limites, et les cartes haut de gamme n'ont pas les mêmes que les autres. Sur un panier élevé, proposer le paiement en plusieurs fois peut débloquer des refus qui n'ont rien à voir avec le solde.

La demande d'autorisation transporte le contexte de la carte, du terminal et du commerçant, jamais le panier. Le code d'activité (MCC) pèse sur le risque et sur les frais.
Une autorisation dure environ deux secondes. Le terminal est l'étape la plus longue, la connexion vers l'acquéreur la plus variable.
Le code de réponse tient sur deux caractères : 00 accepte, 05 refuse sans dire pourquoi. Le solde n'est qu'une des vérifications, la carte a aussi ses propres limites.
Un code peut demander une authentification forte au lieu de refuser : le site envoie le client valider sur son appli, puis relance la demande.
